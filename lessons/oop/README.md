# Модуль 01. ООП в Python

Цель: научиться проектировать объекты с понятной ответственностью, сохранять допустимое состояние и выбирать отношения между компонентами.

Учебный контекст: небольшой backend сервиса заявок. Начинаем с обычных Python-объектов. HTTP, ORM, база данных и внешние API в первом модуле не нужны.

## Основные понятия

| Понятие | Смысл | Пример в backend |
| --- | --- | --- |
| Класс | Описание общего поведения и правил для экземпляров | Модель заявки |
| Объект | Отдельный экземпляр со своим состоянием | Конкретная заявка пользователя |
| Наследование | Специализация типа с сохранением обещаний базового типа | Специализированная заявка |
| Композиция | Объект использует другие объекты как составные части или зависимости | Сервис использует хранилище |
| Полиморфизм | Разные объекты выполняют общий поведенческий контракт | Разные каналы уведомлений |

Инкапсуляция помогает удерживать правила внутри объекта: например, операция не должна оставлять заявку в недопустимом состоянии.

Это ориентиры для размышления, а не готовая схема реализации.

## Что проверяем на review

- Поведение соответствует условиям, включая ошибки и повторные операции.
- У каждого объекта можно кратко назвать ответственность.
- Состояние экземпляров не смешивается.
- Правила предметной области находятся в подходящем месте.
- Наследование сохраняет контракт базового типа.
- Зависимости можно подменить и проверить отдельно.
- Тесты проверяют наблюдаемое поведение.
- Ты можешь объяснить выбор и его ограничения.

Наличие классов само по себе не доказывает качество архитектуры. Сложность должна быть оправдана требованиями.

## Критерий завершения модуля

Все четыре задания приняты. Ты можешь на примере своей реализации объяснить разницу между классом и объектом, наследованием и композицией, а также показать полиморфную замену зависимости.
